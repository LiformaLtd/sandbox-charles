# Audio2Face 2D Face Lab

Standalone SvelteKit 3 / Svelte 5 visual experiment. Development and preview start at port 5173 and advance to the first free port. It animates actual 478-point avatar fits using the compact speech-to-ARKit model and the experimental avatar-specific maps. WebGL warps one neutral texture per avatar. This app imports no production player code and does not change the v1 animation path.

## Run

Requires Node 22.17+ and npm. Use Chrome with WebGPU, or select **Experiment details → CPU · WASM**. `?runtime=cpu` selects CPU at startup. No credentials or remote services are required after dependencies and local assets are installed.

```sh
npm ci
npm run prepare:demo -- \
  --avatars /Users/charleswiles/Source/liforma/source/avatars \
  --maps /Users/charleswiles/Documents/Codex/2026-11-07/we-x20/work/sandbox-mapping/sta/audio2face/.local/mediapipe-mapping-robust-curves-v1 \
  --local-maps /Users/charleswiles/Documents/Codex/2026-11-07/we-x20/work/sandbox-mapping/sta/audio2face/.local/mediapipe-mapping-local-v1 \
  --source-assets /Users/charleswiles/Source/liforma/sandboxes/sandbox-charles/sta/audio2face/.local
npm run dev
```

`prepare:demo` uses `uv` with pinned NumPy and Pillow. An existing Python environment with these packages may instead run `python scripts/prepare_demo.py` with the same arguments. Paths are explicit read-only input dependencies, not implicit sibling imports. The research mapping outputs must already exist. Preparation copies inputs into ignored `static/assets/`; weights, avatar textures, speech and generated maps are never committed. `provenance.json` records the input hashes and paths. One historical snapshot lacking its exact neutral texture is excluded, rather than substituting a different image. There are currently 18 usable fits, including one historical fit.

Development and preview try port 5173, then the first free port. Use the printed URL. For browser tests on a different port, set `TEST_BASE_URL` to that URL. `npm run build` creates a static build; `npm run preview` serves it with the same cross-origin isolation headers required by the speech runtime. No deployment is configured.

## Visual checks

1. Choose an avatar and a recorded speech sample, then **Animate speech**. The six samples were generated by the existing Supertonic pipeline.
2. Pause and scrub using the audio controls. Shape samples follow the audio clock at 60 Hz; rendering follows the display refresh rate. Switch avatars or mapping candidates to inspect the same audio and time.
3. Enable **Show mesh**, **Mouth close-up**, and compare contact correction on/off. Strength zero shows the calibrated reference shape; it may differ slightly from the original fitted neutral mesh because the research mapping repairs/smooths some landmarks.
4. **Type text** generates arbitrary speech locally using the existing sandbox's Phonon setup. This is a convenience input for this visual tool; it is not a change to the proposed production `tts.liforma.ai` contract. **Upload** accepts browser-decodable audio up to 30 seconds / 20 MB. PCM16 mono 16 kHz WAV inputs preserve their samples exactly; other inputs are mixed to mono and resampled to 16 kHz. The same PCM16 samples are used for playback and inference.

The default GPU/CPU checkpoint is the exact existing export verified against the deployed 3D demo, SHA-256 `5f28ddbbaf6f063ab51c90b90c711d2afff7aa1f7fffd1d813813b0a3297ebbd` (2,251,827 bytes). **Experiment details → Reference model** also retains the original mapping baseline (`b4a275acf78b982fb6ec6fc55333c5cf25613e72b6d9b3d80e95d6e74ac6261d`). Neither export has been retrained or altered. Models are checksum-verified, and changing the reference clears prepared playback so tracks from different checkpoints cannot be confused. Calibration artifact provenance continues to identify the original baseline separately.

Preparation reads the default 3D-reference export from `--source-assets/compact-coverage-v2/coverage/runs/control-replay-s37/model.onnx`; `--reference-model /absolute/path/to/model.onnx` can supply the same verified bytes elsewhere. It refuses a different checksum. The optional `--regression-audio /absolute/path/to/james-supertonic.wav` adds **Appointment · exact 3D Supertonic M1**, captured from the working 3D demo. Its checksum is verified. This recording is 5.117 seconds and differs from the 3.68-second Phonon generation of the same text. Use identical audio and checkpoint for a 3D/2D comparison; matching text alone is insufficient.

The complete audio clip is prepared before playback; this experiment is not a streaming player integration.

**Both maps remain experimental.** Geometry + robust linear is the curve-registered mapping candidate; Local nonlinear residual adds a calibrated local correction. These artifacts have not passed the production quality gate. The viewer evaluates their output without claiming to fix their remaining defects. Lip contact correction uses the source rig's verified lip pairs; its explicit toggle allows comparison against raw mapped motion. The source contact capture interval is calibrated from the geometry-matched PP/lip-press poses and the narrowest open speech pose. A midpoint margin defines full capture (about 1.71 mm on the reference rig), with smooth falloff to the open anchor (about 4.29 mm), replacing the overly strict binary 1 mm gate. These are source-rig calibration measurements, not fixed avatar mesh gaps. At full capture, both inner lip contours meet on one shared curve with zero aperture. Outer lip rims rotate with the curve while retaining their thickness. A harmonic skin deformation and pinned-boundary triangle-area projection let nearby vertices follow without relaxing the contact. This replaces the earlier 0.3% residual gap. Reference poses and zero shape strength are preserved; partial activation near the reference blends into contact, and no new model closure events are invented. **Cheek transfer** restores source-rig motion suppressed by the original mouth ownership mask. A bounded local affine fit transfers the source displacement field into each avatar’s calibrated reference geometry, blended over smooth fit-specific cheek patches. Zero restores the previous mapping; 100% is the new default. The transfer uses the predicted jaw/mouth/cheekPuff controls, adds no independent emotional animation, and leaves lip and upper-face landmarks untouched. Maps and this transfer remain experimental and need visual review. A single texture cannot reproduce changing cheek shading or wrinkles. The cavity is a flat fill behind the lip boundary, with no teeth, tongue or appearance model. Neutral texture warping cannot show the final texture quality of the eventual v1 integration.

## Validation

```sh
npm run check
npm test
npm run build
# With npm run dev running:
npm run test:browser
```

Browser tests use the installed macOS Chrome by default; set `CHROME_EXECUTABLE` to another Chrome executable or omit it on non-macOS to use Playwright's installed Chromium. Tests exercise actual CPU inference, upload, local TTS, audio seeking, avatar switching and nonlinear mapping, plus every avatar's assets. Unit checks cover audio-window boundaries, both maps' reference invariance across all fits, independent channel interpolation and exact inference/playback PCM equality.

`src/lib/vendor/compact-{webgpu,mel}.ts` and the two WGSL shaders originate from the existing `sta/audio2face/src/` compact inference implementation. The JavaScript kernels were typed for this independent app, with explicit disposal added. The source sandbox remains unchanged. Avatar triangulation is derived from each fit's stored edges; a fixed outer ring blends moving face geometry back into the static image. This is a diagnostic renderer, not a copy of the production player renderer.
